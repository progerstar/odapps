# ODTemp Logger для Android

Монитор температуры и влажности USB-датчиков ODTEMP-1, ODTEMP-1U,
ODTEMP-1N и ODTEMP-1D. Создан по мотивам настольного
[odtemp-logger](https://github.com/progerstar/odtemp-logger): тот же формат
измерений HID и API UnitX Cloud, отдельный интерфейс на Kotlin и Jetpack Compose.

## Возможности

- Температура и влажность для моделей с датчиком влажности: две линии на общем графике последних 300 показаний, с отдельными шкалами в °C и %.
- Выбор устройства, системное разрешение USB, восстановление соединения после отключения.
- CSV-журналы с настраиваемым интервалом и экспорт через системное окно «Сохранить».
- Отправка новых показаний в UnitX Cloud с отдельным интервалом.
- Наблюдение при свёрнутом приложении: foreground service с уведомлением и кнопкой остановки.
- Светлая и тёмная темы, русский интерфейс.

## Подключение

Нужны Android 7.0 (API 24) или новее, USB Host/OTG и соответствующий кабель.
Root, системный CDC-драйвер и разрешение на доступ ко всему хранилищу не нужны.

1. Подключите датчик через USB OTG.
2. Откройте приложение, нажмите «Подключить» и разрешите доступ к USB.
   Если устройств несколько, выберите нужное по USB description и адресу.
3. Показания появятся после первого отчёта датчика. CSV создаётся, если запись
   включена в настройках; первая свежая запись сохраняется сразу.
4. Для сохранения файла откройте «Журналы» → «Сохранить CSV».
5. Для завершения нажмите «Остановить» в приложении или уведомлении.

Приложение ищет VID `0483`, PID `A26A`, HID-интерфейс с Interrupt IN и проверяет,
что USB product name содержит `ODTEMP` либо равен `UNITX USB NST1001`
(прежнее название датчика NST1001). Один PID используется и другими
устройствами UnitX, поэтому одного совпадения VID/PID недостаточно.

После переподключения сохраняется выбор по USB serial number. Если серийный
номер отсутствует, автоматический выбор возможен при одном устройстве с тем же
product name. Если Android отозвал USB-разрешение, нажмите «Разрешить USB».
При нескольких подходящих датчиках остановите наблюдение и выберите устройство.
Служба не запускается автоматически после перезагрузки телефона или остановки
процесса системой; включите наблюдение снова из приложения.

Во время наблюдения служба удерживает CPU активным, а телефон питает датчик.
Это увеличивает расход батареи. Поведение USB OTG при выключенном экране
зависит также от телефона и его настроек энергосбережения.

## Журнал

Интервал записи: 0,1–86400 секунд, по умолчанию 60 секунд. Внутри приложения
создаётся новый CSV при каждом запуске наблюдения. При восстановлении связи
текущий файл продолжается; повторов последнего показания во время разрыва нет.
Записывается не более одного нового измерения за заданный интервал.
Скорость самих измерений ограничена датчиком.
Стартовое служебное значение «измерение ещё не готово» (`INT16_MIN`) пропускается:
оно не попадает на графики, в журнал и в облако.

```csv
timestamp,temperature_c,humidity_percent
2026-10-16T14:00:00.000+03:00,23.50,45.25
2026-10-16T14:01:00.000+03:00,23.56,45.10
```

Временная метка содержит местное смещение UTC, десятичный разделитель — точка.
У моделей без влажности последнее поле пустое. Текущий журнал также можно
экспортировать: экспорт представляет снимок файла на момент копирования.
Журналы сохраняются в приватной папке `files/logs` и удаляются вместе с приложением.
Перед удалением приложения сохраните нужные файлы. Автоматической очистки нет.

## UnitX Cloud

Остановите наблюдение, откройте «Настройки», включите отправку и укажите:

- адрес сервера: по умолчанию `https://cloud.unitx.pro`;
- ID устройства: по умолчанию `odtemp-1`, 1–64 символа `A–Z a–z 0–9 _ -`;
- write-токен формата `utx1_` + 86 символов base64url;
- интервал отправки: по умолчанию 60 секунд.

Запрос совпадает с настольным приложением:

```http
POST /state/odtemp-1
Authorization: Bearer <write-token>
Content-Type: application/json

{"ty":1,"v1":23.5,"v2":45.25}
```

Без влажности поле `v2` отсутствует. Разрешён только HTTPS; перенаправления
не выполняются. Токен шифруется ключом Android Keystore, резервное копирование
данных приложения отключено. Без включённой отправки приложение не обращается
к серверу.

Отправка и запись CSV имеют независимые интервалы. При ошибке сети следующая
попытка использует новое измерение, история из CSV автоматически не загружается.
Очередь ограничена одним последним показанием, таймаут соединения и чтения —
по 10 секунд. Очень короткий интервал не гарантирует соответствующую частоту
HTTP-запросов. Облачный токен для сборки и тестов не нужен.

## Сборка

Откройте эту папку как отдельный проект в Android Studio или выполните:

```bash
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME=/path/to/android-sdk
./gradlew testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Используются Gradle 9.5.0, Android Gradle Plugin 9.3.1, Kotlin/Compose compiler
2.3.21, Android SDK 37 (`platforms;android-37.0`) и Build Tools 36.0.0,
как в соседнем Android-проекте. Байткод Java — 17.

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
Он подписан отладочным ключом и предназначен для разработки.
`./gradlew assembleRelease` создаёт неподписанный release APK; ключи подписи
в проект не входят. В корне репозитория есть отдельный workflow
`.github/workflows/odtemp-logger-android.yml` со сборкой, тестами и APK-артефактом.

## Устройство проекта

- `protocol/SensorProtocol.kt`: HID report 1, little-endian signed int16 / 100,
  разбор версии прошивки и изменение интервала с сохранением прочих feature-полей.
- `usb/AndroidHidSensor.kt`: Android USB Host, `UsbRequest` для Interrupt IN,
  `GET_REPORT`/`SET_REPORT` feature 4 для интервала.
- `LoggerController.kt`: отдельные интервалы CSV/облака, watchdog, повторное
  подключение; при каждом соединении создаются новые очереди и счётчики интервалов.
- `LoggerService.kt`: служба `connectedDevice`, уведомление и wake lock.
- `data/`: настройки, CSV и клиент UnitX Cloud.
- `ui/`: показания, журналы и настройки на Compose Material 3.

Интервал отчётов датчика при необходимости уменьшается до минимального
запрошенного интервала записи/облака (не более 2 секунд для обновления экрана).
Остальные поля feature report сохраняются; чтение и запись flash отдельными
командами не выполняются. Перевод в загрузчик и обновление прошивки в Android
не перенесены.

## Проверка

Unit-тесты проверяют отрицательную температуру, влажность, длины и ID HID-пакетов,
сохранение полей feature report, интервалы без повторной записи старых значений,
формат облачного JSON, валидацию параметров, CSV в русской локали и экспорт.
Compose-тесты основных состояний экрана находятся в `src/androidTest`:

```bash
./gradlew connectedDebugAndroidTest
```

Для аппаратной проверки на телефоне:

1. Проверить подключение через OTG, разрешение USB и реальные показания каждой модели.
2. У ODTEMP-1D проверить оба значения; у температурных моделей — отсутствие влажности.
3. Отключить кабель: старые показания должны исчезнуть, запись и отправка прекращаются.
   Подключить снова и при необходимости заново разрешить USB.
4. Проверить остановку, повторный запуск, поворот экрана и наблюдение при его выключении.
5. Экспортировать CSV и сверить строки и временные метки с показаниями.
6. На тестовом устройстве в облаке проверить оба формата JSON, успешную отправку,
   ошибку авторизации, отсутствие сети и восстановление сети.

Сборка и автоматические тесты не заменяют проверку физического USB/OTG и облака
с действующим токеном.
