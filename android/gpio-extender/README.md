# GPIO Extender for Android

Android-приложение для управления GPIO Extender 1 и GPIO Extender 2 через USB CDC ACM. Интерфейс — русский, Kotlin + Jetpack Compose Material 3.

## Требования

- Android 7.0 (API 24) или новее с USB Host/OTG;
- GPIO Extender с VID `0483`: PID `A26A` (Extender 2) или `5740` (Extender 1);
- кабель/переходник USB OTG.

Приложение принимает оба PID, но по ним версию не определяет: реальные устройства различаются USB description. Приложение показывает description в статусе и в окне выбора нескольких устройств. Протокол выбирается явно в «Настройках» и сохраняется в DataStore, поэтому неизвестная или изменившаяся строка USB не может включить несовместимый протокол.

## Сборка

```bash
ANDROID_HOME=/home/user/Android/Sdk ./gradlew testDebugUnitTest lintDebug assembleDebug
```

Debug APK создаётся в `app/build/outputs/apk/debug/app-debug.apk`. Приложение не объявляет разрешение `INTERNET`; драйвер `usb-serial-for-android` включён непосредственно в APK.

## Аппаратная проверка

Для каждой версии устройства:

1. Выбрать версию в «Настройках», подключить устройство через OTG и подтвердить системное USB-разрешение.
2. Проверить автоподключение одного устройства и ручной выбор при подключении нескольких устройств с отображением их USB description.
3. Проверить GPIO и ручное обновление. Для v1 убедиться, что выходы до первой подтверждённой команды имеют состояние «неизвестно».
4. Для v2 проверить смену каждого допустимого режима, откат при ошибке, конфликт Capture 4/5, PWM 1…20000 Гц и 0…100 %, затем «Сохранить во flash».
5. Проверить команды с `~` и без него в консоли, очистку журнала, USART, DHT и WS2812-команду `W`.
6. Отключить и снова подключить кабель, убедиться в закрытии старого порта и автоматическом восстановлении соединения.
7. Повторить основные операции в авиарежиме, без root и без системного CDC-драйвера.

Аппаратные пункты требуют физических GPIO Extender и не выполняются обычной Gradle-сборкой.
